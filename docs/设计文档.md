# 《商周大战》应用程序 · 设计文档

> 本文档指导 `codes/商周大战.html`（单文件 HTML+JS）的实现。规则权威来源为 `docs/《商周大战》棋类游戏规则说明书.txt`；若与规则书冲突，以规则书为准。

---

## 一、目标与范围

- **目标**：把《商周大战》规则做成可在浏览器双击运行的桌面棋类应用，本地双人轮流对弈（热座）。
- **范围**：覆盖规则书全部机制——移动/吃子、武王禁锢与解锁、分身、暴走、胜负、平局。首版不含 AI 对手、不含联网、不含存档。
- **非目标**：不做超出规则书的功能扩展（参见全局准则“简单优先”）。

## 二、技术栈与交付物

- 技术栈：纯 HTML + CSS + 原生 JS，无第三方库、无构建步骤。
- 交付物：单个 `codes/商周大战.html` 文件。
- 运行方式：双击文件，浏览器打开即玩。Windows/Mac 通用。
- 渲染：棋盘用 Canvas 绘制；右侧信息面板用 DOM 元素。

选型理由：零安装，对小白最友好；单文件便于分发与后续维护。

## 三、整体架构

单文件内分三层（用注释分隔，不拆文件）：

```
商周大战.html
├ <style>            视觉样式
├ <body>             布局：棋盘 Canvas + 信息面板 + 规则折叠栏
├ <script> 游戏逻辑
│   ├ 数据层    Board/Piece 状态与坐标
│   ├ 规则层    移动/吃子/禁锢/分身/暴走/胜负/平局 判定
│   ├ 渲染层    Canvas 绘制 + 信息面板刷新
│   └ 交互层    点击事件 → 选中 → 高亮 → 落子
└
```

- 数据层只存状态，不碰 DOM。
- 规则层是纯函数，输入局面+动作，输出合法性与新局面。
- 渲染层根据数据层重绘。
- 交互层把鼠标点击翻译成动作，交给规则层校验。

## 四、坐标与数据结构

### 4.1 围棋坐标

- 列字母：`A B C D E F G H J K L M N O P Q R S T`（共 19 列，**跳过 I**）。
- 行数字：`1..19`，行 1 在棋盘**底部**，行 19 在顶部。
- 中心点 `K10`。内部用 `(col, row)` 整数：col∈[0,18]，row∈[0,18]；row=0 对应棋盘第 1 行（底部）。
- 坐标 ↔ 字符串互转：`K19` → col=9, row=18。

### 4.2 王城

| 王城 | 列 | 行 |
|------|----|----|
| 白方（底部） | H,J,K,L,M | 1,2,3,4 |
| 黑方（顶部） | H,J,K,L,M | 16,17,18,19 |

判定函数 `inPalace(side, col, row)`。

### 4.3 初始局面

```json
[
  {"side":"white","type":"king","pos":"K19","state":"imprisoned_invincible"},
  {"side":"black","type":"king","pos":"K1", "state":"imprisoned_invincible"},
  {"side":"black","type":"soldier","pos":"H19"},
  {"side":"black","type":"soldier","pos":"K17"},
  {"side":"black","type":"soldier","pos":"M19"},
  {"side":"white","type":"soldier","pos":"H1"},
  {"side":"white","type":"soldier","pos":"K3"},
  {"side":"white","type":"soldier","pos":"M1"}
]
```

- 白武王 K19 位于**黑方**王城内；黑武王 K1 位于**白方**王城内。
- 各 3 枚敌军棋子在 2 格吃子距离内围困武王（K19 受 H19/K17/M19 围困；K1 受 H1/K3/M1 围困），局面关于 K10 对称。

### 4.4 棋子状态机

每枚棋子字段：
```js
{ id, side: "white"|"black", type: "king"|"soldier"|"clone",
  col, row,
  state: "imprisoned_invincible" | "free" | "berserk",
  isClone: bool }
```

- `type=soldier` → 小棋子。
- `type=king` → 武王本体；`type=clone` → 武王分身（规则上与本体无区别，仅用于区分本体来源）。
- `state`：`imprisoned_invincible`（无敌禁锢，不可动、不可被吃）；`free`（自由，可动、可被吃）；`berserk`（暴走，无限范围，可被吃）。

## 五、核心规则的形式化

### 5.1 移动目标集合 `legalMoves(piece)`

- 普通状态（`free` 或 `imprisoned_invincible` 已解锁后）：横、竖、斜各方向 1 格与 2 格。斜 2 格包含“马步/田字步”，即目标格与起点斜向相差 2 行 2 列即可（不要求中间斜线格空闲）。
- `berserk` 状态：横、竖、斜各方向**无限格**，直到被敌方棋子阻挡（吃子后停）或棋盘边/己方棋子阻挡（穿己方、停于己方棋子的前一格）。

### 5.2 路径与阻挡（核心边界规则）

- 直线 2 格：中间格若有**敌方**棋子，则 2 格目标不可达（路径不穿敌），但中间格这枚敌棋若本身就在 1 格范围内则可被吃。
- 直线 2 格：中间格为己方棋子，可穿过，抵达 2 格目标。
- 斜 2 格：路径格（对角中间格）按同样规则——敌方挡则 2 格不可达，己方可穿。
- 目标格为空 → 移动落子；目标格为敌方棋子 → 吃子落子并停止；目标格为己方棋子 → 不可落子。
- 1 格移动无中间格，只看目标格是否为空或敌方。

> 实现要点：用方向向量 `[(0,±1),(±1,0),(±1,±1)]`，对每个方向按步长 1、2（暴走则 1..N）逐步推进；遇敌方先判能否吃（步长到该格即吃，且不可越过），遇己方则可越过但不可落子于其上。

### 5.3 禁锢判定 `isImprisoned(king, board)`

- 统计**敌方**棋子中，其吃子范围覆盖该武王所在格的数量 `n`。
- `n >= 2` → 处于包围状态。
- 初始局面：每方武王恰好被 3 枚敌军覆盖 → 无敌禁锢生效。
- 注意：禁锢武王自己 `state=imprisoned_invincible` 时不可被吃，但“是否被覆盖”仍按敌方吃子范围统计。

### 5.4 解锁条件

满足任一即解除无敌禁锢，`state` 由 `imprisoned_invincible` → `free`：

1. **被动**：`isImprisoned` 变为 false（围困者 < 2）。武王若仍未移动，后续若再次被 ≥2 敌方覆盖，**重新**进入 `imprisoned_invincible`。
2. **主动**（已确认 Q3）：己方任意 `soldier/clone/king` 移动至该武王的**行动范围**——按武王理论移动范围（普通 2 格、暴走无限）所及格计，**禁锢中的武王也按 2 格范围**计（虽不能动，但范围照算）——完成接应 → 解除禁锢。

解锁后效果：
- 武王可自由移动。
- 武王**首次移动**后：解锁分身能力；同时失去无敌，可被吃（即此后 `state=free` 不再回退到无敌）。

### 5.5 分身

- 触发：己方 `soldier` 进入己方任一武王的行动范围 → 可选择转化为 `clone`（大棋子）。
- **回合消耗（已确认 Q1）**：变身**不额外消耗回合**。即：士兵”移动进入武王范围”是本回合的一次行动，到达后选择变身是附属于该次移动的即时可选效果，不再产生第二次行动；该次移动完成后回合结束。换言之，士兵这一步走到武王范围内 → 可选变身 → 回合结束。

- 上限：场上每方同时存在的 `king+clone` 总数 ≤ 2。
- 补满：分身被吃后，可继续转化新分身，只要总数不超 2。
- 暴走后：该方所有武王失去分身能力（不能再新转化），但已存在的分身可继续行棋、可各自进入暴走。

### 5.6 暴走

- 触发：己方任意 `king/clone` 踏入**己方**王城 → 该枚获得 `state=berserk`。
- 效果：该枚可直线/斜线走无限格（路径规则同 5.2，但无 2 格上限）。
- `berserk` 非无敌，可被吃。
- 触发暴走的同时：
  - 己方所有武王失去分身能力（不再转化新分身）。
  - **对方武王解除无敌禁锢** → 对方所有 `imprisoned_invincible` 的 king 转 `free`（一次性、不可逆）。

### 5.7 胜负判定（每次行动后检查）

- **胜**：击杀对方全部武王，且己方王处于解锁状态（`free` 或 `berserk`）。
  - 若对方有分身，须击杀对方场上**全部** `king+clone`。
  - “迎回己方的王”（已确认 Q2）：泛指己方王解除禁锢即可，**不**要求本体回到己方王城。
  - 若击杀对方王时己方王仍禁锢 → 不立即判胜，继续对弈直到己方王解锁为止。
- **负**（被动）：己方武王处于禁锢，且其余小棋子全部被吃 → 直接判负。
- **停棋负**：轮到一方必须行棋，无合法行动时判负。（首版：若无合法移动则直接判负，不做”放弃”按钮。）

### 5.8 平局

- 棋子循环走位 3 回合不变 → 平局。
- 实现：记录最近局面哈希序列，若同一局面在最近 6 次行动内出现 ≥3 次（即循环 3 回合）→ 判平局。首版可简化为“同一局面出现 3 次即平局”。

## 六、交互流程

状态机：`IDLE` → `SELECTED` → `IDLE`（落子后）。

1. `IDLE`：点击己方棋子（当前回合方）→ 若可行动，进入 `SELECTED`，高亮可走格（绿色=空/可走，红色=可吃）。
2. `SELECTED`：点击高亮格 → 执行移动/吃子；若点击的是分身转化机会格（己方武王范围内），弹“是否转化为分身”小确认。
3. 落子后：结算禁锢/解锁/暴走/胜负/平局，切换回合，回 `IDLE`。
4. 任何时候点空白或非高亮格 → 取消选择，回 `IDLE`。

非法点击（不是当前回合方、不可动棋子、非高亮格）→ 静默忽略或提示。

3. **M3 禁锢与解锁** → 验证：初始禁锢不可动、被动解锁（吃掉/移走围困者）、主动解锁（己方进入范围）。

## 九、已澄清结论

- **Q1 分身”不消耗本回合行动”**：变身**不额外消耗回合**。士兵移动进入武王范围是本回合一次行动，到达后可选变身（附属该次移动的即时效果），该次移动完成后回合结束。
- **Q2 “迎回己方的王”**：泛指**己方王解除禁锢**即可，不要求本体回到己方王城。
- **Q3 主动解锁”行动范围”**：按武王理论移动范围（普通 2 格）计，禁锢中的武王也按 2 格范围计。
- **Q4 停棋判负**：规则书明确”不存在停棋”，实现为无合法行动即判负。
