# 联机对战设计文档

## 1. 架构概述

### 1.1 系统架构

```
┌─────────────┐      WebSocket (局域网)      ┌─────────────┐
│   玩家 A    │◄───────────────────────────►│   主机电脑  │
│  (浏览器)   │                              │ (Node.js)   │
└─────────────┘                              └─────────────┘
                                                    ▲
                                                    │ WebSocket
                                                    ▼
                                            ┌─────────────┐
                                            │   玩家 B    │
                                            │  (浏览器)   │
                                            └─────────────┘
```

### 1.2 技术选型

| 技术 | 说明 |
|------|------|
| WebSocket | 全双工实时通信，延迟低 |
| Node.js + ws 库 | 服务端运行环境，零依赖 |
| 局域网直连 | 无需外部服务器，无需域名/证书 |

### 1.3 文件结构

```
商周大战/
├── server.js              # Node.js 服务器
├── package.json           # 项目配置
├── start-server.bat       # Windows 一键启动脚本
├── codes/
│   └── 商周大战.html      # 客户端（含联机模块）
├── index.html             # 主入口
└── docs/
    └── 联机对战设计文档.md  # 本文档
```

## 2. 服务端设计（server.js）

### 2.1 核心职责

| 职责 | 说明 |
|------|------|
| 房间管理 | 创建房间（生成 6 位房间码）、加入房间、销毁房间 |
| 消息中转 | 将一方的落子/悔棋请求转发给另一方 |
| 断线处理 | 检测连接关闭，通知对手，延迟销毁房间 |
| 布局同步 | 房主选择的布局同步给加入者 |
| 倒计时广播 | 走子/开局/悔棋后广播倒计时启动信号 |

### 2.2 房间数据结构

```javascript
rooms.set(roomId, {
  players: [ws],                              // 当前在线 WebSocket 列表
  state: { created: Date.now() },             // 房间状态
  gameState: null,                            // 缓存的棋局数据（断线重连用）
  playerSlots: { white: ws, black: null },    // 按颜色记玩家引用
  disconnectTimer: null,                      // 延迟销毁定时器
  preset: 'battle'                            // 房主选择的布局
});
```

### 2.3 消息协议

#### 客户端 → 服务器

| 类型 | 字段 | 说明 |
|------|------|------|
| `create-room` | `preset` | 创建房间（携带布局名） |
| `join-room` | `roomId` | 加入房间 |
| `leave-room` | `roomId` | 主动退出房间（不断连接） |
| `rejoin-room` | `roomId`, `side` | 断线重连 |
| `cache-game-state` | `roomId`, `data` | 缓存棋局 |
| `move` | `roomId`, `data` | 发送落子 |
| `undo-request` | `roomId` | 请求悔棋 |
| `undo-approve` | `roomId` | 同意悔棋 |
| `undo-reject` | `roomId` | 拒绝悔棋 |
| `sync` | `roomId`, `data` | 同步局面 |
| `chat` | `roomId`, `message` | 聊天消息 |

#### 服务器 → 客户端

| 类型 | 字段 | 说明 |
|------|------|------|
| `room-created` | `roomId` | 房间创建成功 |
| `game-start` | `side`, `preset` | 对手加入，游戏开始（携带布局） |
| `move` | `data` | 收到对手落子 |
| `undo-request` | - | 收到悔棋请求（精确发给对手） |
| `undo-approve` | - | 对手同意悔棋 |
| `undo-reject` | - | 对手拒绝悔棋 |
| `do-undo` | `count` | 执行悔棋（count 步数，默认 2） |
| `timer-start` | `side` | 倒计时启动（广播给双方） |
| `game-state` | `data` | 重连时下发缓存棋局 |
| `opponent-disconnected` | `timeout` | 对手断线通知 |
| `opponent-rejoined` | - | 对手已重连 |
| `opponent-left` | - | 对手主动离开 |
| `request-sync` | - | 请求对手发送棋局同步 |
| `error` | `message` | 错误信息 |

## 3. 客户端设计

### 3.1 状态变量

```javascript
/* 联机对战状态 */
let ws = null;              // WebSocket 连接
let onlineMode = false;     // 是否联机模式
let roomId = null;          // 当前房间号
let mySide = null;          // 我执的颜色 "white"/"black"
let isHost = false;         // 是否房主
let opponentConnected = false; // 对手是否已连接

/* 断线重连 */
let reconnectInfo = null;   // { roomId, side, addr }
let reconnectTimer = null;
let reconnectAttempts = 0;

/* 联机倒计时 */
let timerInterval = null;
let timerRemaining = 0;
let timerActiveSide = null; // 当前倒计时行棋方
const TIMER_DEFAULT = 30;   // 30 秒
```

### 3.2 核心函数

| 函数 | 职责 |
|------|------|
| `connectToServer(addr)` | 连接 WebSocket 服务器 |
| `handleServerMessage(msg)` | 分发处理服务器消息 |
| `createRoom()` | 创建房间（发送当前布局） |
| `joinRoom()` | 加入房间 |
| `exitOnlineGame()` | 退出房间（不断连接） |
| `sendMoveToServer(piece, col, row, cap)` | 发送落子数据 |
| `receiveOpponentMove(data)` | 接收并执行对手落子 |
| `sendUndoRequest()` | 发送悔棋请求（仅己方回合） |
| `showUndoPrompt()` | 非阻塞悔棋确认（按钮替代 confirm） |
| `receiveSync(data)` | 接收局面同步 |
| `syncOnlinePanelUI()` | 联机面板折叠/展开 |
| `syncOnlinePlayControls()` | 联机模式按钮切换 |
| `handleTimerStart(side)` | 处理倒计时启动 |
| `renderTimerDisplay()` | 渲染倒计时显示 |
| `aiTimeoutMove()` | 超时 AI 代走 |

### 3.3 走子同步流程

```
人类落子
    ↓
finishTurn() → stopTimer()
    ↓
settleMove() → 记谱 → 渲染
    ↓
sendMoveToServer()  ────────►  服务器  ────────►  对手
                                        │
                                        ├── 转发 move
                                        └── 广播 timer-start（下一回合方）
                                               ↓
                                    对手 receiveOpponentMove()
                                               ↓
                                    doMove() → settleMove() → 渲染
                                               ↓
                                    双方显示倒计时
```

### 3.4 悔棋协商流程

```
玩家 A 点击悔棋（仅己方回合可用）
    ↓
sendUndoRequest()  ────────►  服务器（精确发给 B，不广播）
                                        ↓
                               玩家 B 显示按钮提示
                               "对方请求悔棋 [同意] [拒绝]"
                                   ↓           ↓
                                 同意         拒绝
                                   ↓           ↓
                           undo-approve   undo-reject
                                   ↓           ↓
                           服务器发 do-undo   通知 A 被拒绝
                           (count: 2, 双方)
                                   ↓
                           双方各退两步
                           服务器广播 timer-start
```

### 3.5 倒计时流程

```
服务器广播 timer-start { side: "white" }
    ↓
双方客户端 handleTimerStart("white")
    ↓
显示："我方AI小菜鸡请求出战：30"（行棋方）
  或："敌方白棋行棋倒计时：30"（等待方）
    ↓
双方运行 setInterval 递减
    ↓
≤5 秒时变红闪烁
    ↓
归零时：
  - 行棋方：stopTimer() → aiTimeoutMove() → AI 代走
  - 等待方：stopTimer()（等对手走子消息）
```

### 3.6 断线重连流程

```
玩家 A 断线
    ↓
服务端 handleDisconnect：
  - playerSlots[side] = null
  - 启动 60s 销毁定时器
  - 通知 B: opponent-disconnected
    ↓
A 客户端 ws.onclose：
  - reconnectInfo 存在 → attemptReconnect()
  - 每 3s 重连一次，最多 10 次
    ↓
A 重连成功 → ws.onopen：
  - 发送 rejoin-room { roomId, side }
    ↓
服务端 handleRejoinRoom：
  - 验证槽位为空
  - 替换 WebSocket 引用
  - 取消销毁定时器
  - 发送 game-state（缓存棋局）
  - 通知 B: opponent-rejoined
    ↓
A 收到 game-state → receiveSync() 恢复棋局
B 收到 opponent-rejoined → 显示"对手已重连"
    ↓
对局继续
```

### 3.7 联机 UI 模式

进入房间后（`roomId !== null`）：
- **隐藏**：新局、还原布局、摆子、撤销悔棋、复盘、导出、导入、规则
- **显示**：悔棋（仅己方回合+已走过棋时可用）、退出房间
- **禁用**：布局选择器

退出房间后恢复全部按钮。

### 3.8 布局同步

- 创建房间时发送 `{ type: "create-room", preset: currentPreset }`
- 服务器存储 `room.preset`
- 加入者收到 `game-start` 时，强制切换到房主的布局
- 联机期间布局选择器禁用

## 4. 关键修改点

| 位置 | 修改内容 |
|------|---------|
| `finishTurn` | 联机模式下调用 `sendMoveToServer` 而非 `aiMaybeSchedule`；调用 `stopTimer()` |
| `aiPlayMove` | 联机模式下调用 `sendMoveToServer`（超时 AI 代走后同步） |
| `humanUndo` | 联机模式下调用 `sendUndoRequest`（仅己方回合） |
| `render()` | 悔棋按钮加 `(onlineMode && (turn !== mySide \|\| stepCount < 2))` 禁用；布局加 `!!roomId` 禁用 |
| canvas click | 增加 `onlineMode && turn !== mySide` 守卫 |
| opponent change | 增加 `"remote"` 选项处理 |
| `game-start` | 同步布局、设置 roomId、调用 `syncOnlinePlayControls()` |
| `room-created` | 禁用"加入"按钮 |

## 5. 安全与限制

### 5.1 当前限制

| 项目 | 说明 |
|------|------|
| 认证 | 无用户认证，仅靠房间号区分 |
| 防作弊 | 无服务端校验，信任客户端数据 |
| 观战 | 不支持观战模式 |

### 5.2 已实现功能

| 功能 | 说明 |
|------|------|
| 断线重连 | localStorage 保存重连信息，自动重连，服务端缓存棋局 |
| 布局同步 | 房主布局自动同步给加入者 |
| 行棋倒计时 | 30 秒倒计时，超时 5 级 AI 代走 |
| 悔棋协商 | 非阻塞按钮确认，退两步（对手+自己） |
| 退出房间 | 不断开连接，可重新创建/加入房间 |

## 6. 部署说明

### 6.1 环境要求

- Node.js 18+
- 局域网内两台电脑（或同一电脑两个浏览器标签页测试）

### 6.2 启动方式

```bash
# 安装依赖（首次）
npm install

# 启动服务器
node server.js

# 或双击 start-server.bat
```

### 6.3 防火墙配置

如果客户端无法连接，需要在主机电脑放行 8080 端口：

```bash
# Windows（管理员权限运行）
netsh advfirewall firewall add rule name="商周大战联机" dir=in action=allow protocol=TCP localport=8080
```

## 7. 测试方案

### 7.1 本机测试

1. 启动服务器：`node server.js`
2. 打开两个浏览器标签页，都访问 `codes/商周大战.html`
3. 标签页 A：选择联机 → 连接 → 创建房间
4. 标签页 B：选择联机 → 连接 → 输入房间号 → 加入
5. 验证：布局同步、落子同步、倒计时、悔棋、退出房间

### 7.2 局域网测试

1. 电脑 A 启动服务器
2. 电脑 B 输入电脑 A 的 IP 地址连接
3. 验证完整对局流程

### 7.3 断线重连测试

1. 对局进行中断开一方网络
2. 验证对手端显示"对手断线"
3. 恢复网络，验证自动重连和棋局恢复

### 7.4 超时测试

1. 开始对局，等待 30 秒不行棋
2. 验证 AI 自动代走
3. 验证走子同步给对手
