# 联机对战设计文档

## 1. 架构概述

### 1.1 系统架构

```
┌─────────────┐      WebSocket (局域网)      ┌─────────────┐
│   玩家 A    │◄───────────────────────────►│   主机电脑  │
│  (浏览器)   │                              │ (Node.js)   │
└─────────────┘                              └─────────────┘
                                                    ▲
                                                    │ WebSocket
                                                    ▼
                                            ┌─────────────┐
                                            │   玩家 B    │
                                            │  (浏览器)   │
                                            └─────────────┘
```

### 1.2 技术选型

| 技术 | 说明 |
|------|------|
| WebSocket | 全双工实时通信，延迟低 |
| Node.js + ws 库 | 服务端运行环境，零依赖 |
| 局域网直连 | 无需外部服务器，无需域名/证书 |

### 1.3 文件结构

```
商周大战/
├── server.js              # Node.js 服务器
├── package.json           # 项目配置
├── start-server.bat       # Windows 一键启动脚本
├── codes/
│   └── 商周大战.html      # 客户端（含联机模块）
└── index.html             # 主入口
```

## 2. 服务端设计（server.js）

### 2.1 核心职责

| 职责 | 说明 |
|------|------|
| 房间管理 | 创建房间（生成 6 位房间码）、加入房间、销毁房间 |
| 消息中转 | 将一方的落子/悔棋请求转发给另一方 |
| 断线处理 | 检测连接关闭，通知对手 |

### 2.2 房间数据结构

```javascript
const rooms = new Map(); // roomId → { players: [ws1, ws2], state: {...} }
```

- `roomId`：6 位数字字符串
- `players`：WebSocket 连接数组，最多 2 个
- `state`：房间状态（创建时间等）

### 2.3 消息协议

#### 客户端 → 服务器

| 类型 | 字段 | 说明 |
|------|------|------|
| `create-room` | - | 创建房间 |
| `join-room` | `roomId` | 加入房间 |
| `move` | `roomId`, `data` | 发送落子 |
| `undo-request` | `roomId` | 请求悔棋 |
| `undo-approve` | `roomId` | 同意悔棋 |
| `undo-reject` | `roomId` | 拒绝悔棋 |
| `sync` | `roomId`, `data` | 同步局面 |

#### 服务器 → 客户端

| 类型 | 字段 | 说明 |
|------|------|------|
| `room-created` | `roomId` | 房间创建成功 |
| `game-start` | `side` | 对手加入，游戏开始 |
| `move` | `data` | 收到对手落子 |
| `undo-request` | - | 收到悔棋请求 |
| `do-undo` | - | 执行悔棋 |
| `opponent-left` | - | 对手断线 |
| `error` | `message` | 错误信息 |

### 2.4 消息格式示例

```json
// 创建房间
{ "type": "create-room" }
// 响应
{ "type": "room-created", "roomId": "123456" }

// 加入房间
{ "type": "join-room", "roomId": "123456" }
// 响应（双方都会收到）
{ "type": "game-start", "side": "black" }

// 落子
{
  "type": "move",
  "roomId": "123456",
  "data": {
    "pieceId": 5,
    "fromCol": 9, "fromRow": 18,
    "toCol": 9, "toRow": 16,
    "capture": false
  }
}
```

## 3. 客户端设计

### 3.1 状态变量

```javascript
let ws = null;              // WebSocket 连接
let onlineMode = false;     // 是否联机模式
let roomId = null;          // 当前房间号
let mySide = null;          // 我执的颜色 "white"/"black"
let isHost = false;         // 是否房主
let opponentConnected = false; // 对手是否已连接
```

### 3.2 核心函数

| 函数 | 行号 | 职责 |
|------|------|------|
| `connectToServer` | - | 连接 WebSocket 服务器 |
| `handleServerMessage` | - | 处理服务器消息 |
| `createRoom` | - | 创建房间 |
| `joinRoom` | - | 加入房间 |
| `sendMoveToServer` | - | 发送落子数据 |
| `receiveOpponentMove` | - | 接收并执行对手落子 |
| `sendUndoRequest` | - | 发送悔棋请求 |
| `receiveSync` | - | 接收局面同步 |

### 3.3 走子同步流程

```
人类落子
    ↓
finishTurn()
    ↓
settleMove() → 记谱 → 渲染
    ↓
sendMoveToServer()  ────────►  服务器  ────────►  对手
                                        ↓
                               receiveOpponentMove()
                                        ↓
                               doMove() → settleMove() → 渲染
```

### 3.4 悔棋协商流程

```
玩家 A 点击悔棋
    ↓
sendUndoRequest()  ────────►  服务器  ────────►  玩家 B
                                        ↓
                               confirm("对方请求悔棋，是否同意？")
                                   ↓           ↓
                                 同意         拒绝
                                   ↓           ↓
                           undo-approve   undo-reject
                                   ↓           ↓
                           双方执行悔棋   通知玩家 A
```

### 3.5 关键修改点

| 位置 | 修改内容 |
|------|---------|
| `finishTurn` | 联机模式下调用 `sendMoveToServer` 而非 `aiMaybeSchedule` |
| `humanUndo` | 联机模式下调用 `sendUndoRequest` 而非直接 `undo` |
| canvas click | 增加 `onlineMode && turn !== mySide` 守卫 |
| opponent change | 增加 `"remote"` 选项处理 |

## 4. 安全与限制

### 4.1 当前限制

| 项目 | 说明 |
|------|------|
| 认证 | 无用户认证，仅靠房间号区分 |
| 防作弊 | 无服务端校验，信任客户端数据 |
| 断线重连 | 仅提示断线，不支持自动重连 |
| 观战 | 不支持观战模式 |

### 4.2 未来扩展

| 功能 | 实现思路 |
|------|---------|
| 断线重连 | 客户端保存房间号，重连后请求同步 |
| 防作弊 | 服务器校验走法合法性 |
| 观战 | 房间增加第 3 个连接，只收不同发 |
| 匹配系统 | 服务器维护等待队列，自动配对 |

## 5. 部署说明

### 5.1 环境要求

- Node.js 18+
- 局域网内两台电脑（或同一电脑两个浏览器标签页测试）

### 5.2 启动方式

```bash
# 安装依赖（首次）
npm install

# 启动服务器
node server.js

# 或双击 start-server.bat
```

### 5.3 防火墙配置

如果客户端无法连接，需要在主机电脑放行 8080 端口：

```bash
# Windows（管理员权限运行）
netsh advfirewall firewall add rule name="商周大战联机" dir=in action=allow protocol=TCP localport=8080
```

## 6. 断线重连方案

### 6.1 问题分析

当前实现中，玩家断线后：
- 服务端直接从 `room.players` 移除该玩家
- 通知对手"对手已离开"
- 如果双方都断开，房间立即销毁
- 棋局状态仅存在于客户端内存，服务端不缓存

结果：掉线 = 丢失对局，无法恢复。

### 6.2 设计目标

- 玩家断线后，房间保留 60 秒等待重连
- 重连后自动恢复棋局，对局继续
- 对手端能看到"对手断线/已重连"的状态提示

### 6.3 服务端改动

#### 房间数据结构扩展

```javascript
rooms.set(roomId, {
  players: [ws],
  state: { created: Date.now() },
  // 新增 ↓
  gameState: null,                        // 缓存的棋局数据
  playerSlots: { white: ws, black: null }, // 按颜色记玩家
  disconnectTimer: null                    // 延迟销毁定时器
});
```

#### 断线处理改进

`handleDisconnect` 不再直接删除玩家：
1. 将该玩家的槽位（`playerSlots.white` 或 `playerSlots.black`）置为 `null`
2. 启动 60 秒销毁定时器
3. 通知对手 `{ type: "opponent-disconnected", timeout: 60 }`
4. 60 秒内无人重连 → 才真正销毁房间

#### 新增 `rejoin-room` 消息处理

```
客户端 → 服务器: { type: "rejoin-room", roomId, side }
```

处理流程：
1. 验证房间存在
2. 验证该颜色槽位为空（原玩家已断线）
3. 替换该槽位的 WebSocket 引用
4. 取消销毁定时器
5. 把缓存的 `gameState` 发给重连方：`{ type: "game-state", data: gameState }`
6. 通知对手：`{ type: "opponent-rejoined" }`

#### 棋局状态缓存

新增 `cache-game-state` 消息类型，客户端每次走子后发一份完整棋局给服务端缓存到 `room.gameState`。

### 6.4 客户端改动

#### 断线自动重连

```javascript
let reconnectInfo = null; // { roomId, side, addr }
```

- `game-start` 时保存重连信息
- `ws.onclose` 中，如果 `reconnectInfo` 存在：
  - 显示"连接断开，正在重连..."
  - 每 3 秒尝试重连一次，最多 10 次
  - 重连成功后发 `rejoin-room`

#### 新增消息处理

| 消息类型 | 处理逻辑 |
|---------|---------|
| `game-state` | 调用 `receiveSync(data)` 恢复棋局 |
| `opponent-disconnected` | 显示"对手断线，等待重连中（60秒）..." |
| `opponent-rejoined` | 显示"对手已重连"，恢复 `opponentConnected` |

### 6.5 消息协议新增

| 方向 | 类型 | 字段 | 说明 |
|------|------|------|------|
| C→S | `rejoin-room` | `roomId`, `side` | 重连加入房间 |
| C→S | `cache-game-state` | `roomId`, `data` | 缓存棋局 |
| S→C | `game-state` | `data` | 重连时下发棋局 |
| S→C | `opponent-disconnected` | `timeout` | 对手断线通知 |
| S→C | `opponent-rejoined` | - | 对手已重连 |

### 6.6 重连流程图

```
玩家 A 正在游戏中
    ↓
网络断开（浏览器关闭/网络波动）
    ↓
服务端检测到 A 断线
    ↓
A 的槽位置 null，启动 60s 定时器
通知 B: opponent-disconnected
    ↓
A 重新打开页面 / 网络恢复
    ↓
客户端自动重连 WebSocket
发送 rejoin-room { roomId, side }
    ↓
服务端验证通过
取消销毁定时器
发送 game-state 给 A
通知 B: opponent-rejoined
    ↓
A 收到 game-state → receiveSync() 恢复棋局
B 收到 opponent-rejoined → 显示"对手已重连"
    ↓
对局继续
```

## 7. 测试方案

### 6.1 本机测试

1. 启动服务器：`node server.js`
2. 打开两个浏览器标签页，都访问游戏
3. 标签页 A：选择联机 → 连接 → 创建房间
4. 标签页 B：选择联机 → 连接 → 输入房间号 → 加入
5. 验证落子同步、悔棋协商、断线提示

### 6.2 局域网测试

1. 电脑 A 启动服务器
2. 电脑 B 输入电脑 A 的 IP 地址连接
3. 验证完整对局流程
