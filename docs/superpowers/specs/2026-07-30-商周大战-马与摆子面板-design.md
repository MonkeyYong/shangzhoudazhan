## 2. 走法 / 规则（标准骑士）

- 新增常量 `KNIGHT_OFFSETS = [[2,1],[2,-1],[-2,1],[-2,-1],[1,2],[1,-2],[-1,2],[-1,-2]]`。
- `reachableCells`（`:934`）：在 `imprisoned_invincible` 早返之后、`DIRS` 扫描之前加分叉：
  ```
  if (piece.type === "horse") return knightReach(piece);
  ```
  `knightReach(piece)` 遍历 8 偏移，越界丢；目标格：空着→加入 `{capture:false}`；敌方→加入 `{capture:true}`；己方/无敌王（`king && !hasMoved`）→丢弃。马**不受阻挡**，不做"路径穿敌"检查。
- `simGenMoves`（`:1712`）：在 `imprisoned_invincible` 早返后加对称分叉，用 `KNIGHT_OFFSETS` 与相同的"空着/敌方吃/己方与无敌王丢"语义产出 moves；`simHasReach` 同。
- `isImprisoned`（`:980`）、`activeUnlockCheck`（`:1011`）、`cloneOfferCheck` 自动正确——马是小棋子，参与禁锢覆盖、可触发主动解锁、可作分身候选。
- `soldiersOf`（`:1084`）重命名为 **`smallPieceCountOf(side)`** = `soldier + horse`（含未来小棋子）。`checkWinLoss`（`:1092-1093`）改用之，满足规则 7.3。
- `aiCloneOption`（`:1757`）的 `p.type === "soldier"` 改为"非 king/clone 即小棋子"判定（`p.type !== "king" && p.type !== "clone"`），让马也算。
- 马无 `berserk` 状态（仅 king 享）；`simEval` 中马按 `AI_VAL.horse=300` 计入材质，不享受 king 状态加成（imprisoned -500 / 未移动 +200 / berserk +400）。
- 模拟器哈希 `simHash`（`:1842`）的 `Z_TYPE[p.type]` 已有 horse=3，无需额外改动。

## 5. 导出 / 导入布局

- `exportLayout()`（新增）：
  - 输出 `{game:"商周大战", preset:"custom", moves:[], layout: pieces.map(p=>[p.side,p.type,p.col,p.row])}`。
  - `JSON.stringify(_,null,2)` → `Blob` → `<a download="商周大战布局.json">` 触发下载。
  - 沿用 `exportRecord`（`:2768`）的 blob/anchor/cleanup 套路。
- `importLayout(e)`（新增）：
  - `FileReader` → `JSON.parse` → `data.layout.map(normLayoutItem).filter(Boolean)`。
  - 若 `!setupMode` → hint 提示"请先进摆子"，return。
  - `confirm("导入布局将覆盖当前摆子，是否继续？")` 否 → return。
  - 用 layout 重建 `pieces`：建议先把 `initPieces`（`:887-903`）里 `data.map(d => ({...}))` 抽成小函数 `piecesFromLayout(data)`（设置 `id: makeId()`、`state: king→"imprisoned_invincible" / 否则 "free"`、`isClone: false`、`hasMoved: false`、`activelyUnlocked: false`、`hoverT: 0`），initPieces 与 importLayout 都调它，避免字段清单漂移。importLayout 调用 `pieces = piecesFromLayout(filteredLayout)`。
  - `markSetupDirty()`（`:2915`）→ `render()` → hint 提示"已导入 N 个棋子"。
- 入口：摆子面板 `.setup-actions` 第 2 组两按钮 + hidden `<input type="file" id="file-import-layout" accept=".json,application/json">`；事件在 `DOMContentLoaded` 同款位置绑定。
- **不动** 现有 `exportRecord`/`importRecord`（棋谱复盘路径保持独立）。

## 6. 错误处理

- `normLayoutItem`：未知 `type` 返 `null`（不抛错）；`importLayout` 若过滤后 `layout.length === 0` → hint 提示"布局为空或格式不符"。
- JSON 解析失败 → `importLayout` catch 块设 hint 报错；不破坏当前摆子状态。
- 导出文件名冲突由浏览器处理。
- `validateSetup`（`:2956`）：
  - "≥1 soldier" → "≥1 smallPiece"（用 `smallPieceCountOf`）。
  - "禁锢王 + 0 soldier" → "禁锢王 + 0 smallPiece"。
  - 保留三道闸：双方各 1 王、双方各 ≥1 小棋子、双方有合法行动。

## 10. 动态加载初始布局

### 10.1 文件位置与命名

新增 `codes/layouts/` 目录，三个文件（**初值等于当前 `buildLayout(key)` 的输出**，保证零行为变化）：
- `codes/layouts/small.json` — 小战 14 子
- `codes/layouts/battle.json` — 大战 22 子（默认）
- `codes/layouts/final.json` — 决战 34 子

文件 schema 与"导出布局"完全一致：
```json
{
  "game": "商周大战",
  "preset": "small|battle|final",
  "layout": [["white","king",9,18], ["black","king",9,0], ...]
}
```

### 10.2 加载时机与缓存

- `DOMContentLoaded` 时新增 `loadPresetLayouts()`：
  ```
  Promise.all([
    fetch("codes/layouts/small.json").then(r=>r.json()),
    fetch("codes/layouts/battle.json").then(r=>r.json()),
    fetch("codes/layouts/final.json").then(r=>r.json()),
  ]).then(([s,b,f]) => {
    loadedLayouts = {
      small:  validateLoadedLayout(s.layout, "small"),
      battle: validateLoadedLayout(b.layout, "battle"),
      final:  validateLoadedLayout(f.layout, "final"),
    };
    layoutsReady = true;
    enablePresetSelect();
    clearHint();
  }).catch(err => console.warn("layouts load failed", err));
  ```
- `initPieces`（`:887-902`）：仅改 else 分支右值，一行：
  ```
  if (currentPreset === "custom") { data = customLayout || []; }
  else { data = loadedLayouts[currentPreset] || PRESETS[currentPreset].layout; }
  ```
  加载完成前的极短窗口里行为不变（用硬编码），加载完成后自动切到新文件。

### 10.3 加载 UX

- `!layoutsReady` 时：档位 `<select id="preset">` `disabled`，hint 显示"加载布局…"。
- 加载完成（或某文件失败）后取消禁用、清提示。
- 任一文件失败：仅该档位回落硬编码 + `console.warn`；其余档位不受影响（独立 Promise）。

### 10.4 校验与对称

`validateLoadedLayout(layout, key)`：
1. 数组化 + `normLayoutItem.filter(Boolean)`。
2. **K10 对称校验**：遍历 `layout`，对每条 `[side,type,c,r]`，要求存在 `[opposite(type不变), opposite(side), 18-c, 18-r]`；反向亦然。
3. 必须含双方各 1 king（与硬编码一致）。
4. 任一步失败 → 返 `null`（调用方回落硬编码）+ `console.warn`。

这把规则 二.4"双方布局完全相同"显式化：手改 JSON 弄歪对称会被自动拒绝。

### 10.5 与现有代码的关系

- `WHITE_HALF`（`:507`）+ `buildLayout`（`:530`）+ `PRESETS`（`:538`）**保留**作为兜底，逻辑零改动。
- 新增全局：`loadedLayouts = {}`、`layoutsReady = false`、`loadPresetLayouts()`、`validateLoadedLayout(layout, key)`。
- `initPieces`（`:887-902`）一行改动（见 10.2）。
- 加载完成后可选择性 `render()` 一次以反映新数据（如果当前未在对局中）。

### 10.6 编辑工作流

1. 编辑 `codes/layouts/<key>.json`（保持 K10 对称，含双方各 1 king）。
2. 浏览器刷新页面 → 自动 fetch 新内容。
3. 对称错则控制台 warn，回落硬编码，游戏不崩。

### 10.7 不做

- 不做运行时"重载布局"按钮（刷新即重载）。
- 不做布局文件版本号/签名。
- 不动 `codes/商周大战棋谱 (自定义-决战).json`（用户棋谱，与初始布局文件无关）。
