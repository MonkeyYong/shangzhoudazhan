# 商周大战 · 摆子每档独立保存 · 设计文档

- 日期：2026-07-31
- 状态：已批准，待实施
- 范围：单 HTML 项目 `codes/商周大战.html`（`index.html` 由 `sync-index.bat` 同步）+ `codes/layouts/custom.json`（新增，可选）
- 前置：上一轮「马与摆子面板」已落地（spec `2026-07-30-…-design.md`），摆子面板基础能力在位
- 关键决定摘要（来自 brainstorming）：
  1. 每个档位都能就地编辑、单独保存到 `codes/layouts/{preset}.json`；不再有"自动切到自定义"机制。
  2. 保存 = 浏览器下载 `{preset}.json`，由用户覆盖到 `codes/layouts/` 后刷新页面生效。提示信息写明目标路径。
  3. 「自定义」作为四档之一（`custom.json`）与其他内置档同源处理；不再读写 `localStorage`。
  4. 删除 `localStorage` 的 `CUSTOM_LAYOUT_KEY` / `loadCustomLayout` / `saveCustomLayout` / `syncCustomSub`，对应代码统一改造。

## 1. 行为变更表

| 触发 | 旧行为 | 新行为 |
|---|---|---|
| 进入摆子（"摆子 ✎"） | snapshot + 记 entry preset | **不变** |
| 摆子中首次改棋 `markSetupDirty` | 把 `currentPreset` 切到 `"custom"` | **不再切档**；仅置 `setupDirty = true`，`currentPreset` 维持原值 |
| 「校验并保存」 | `currentPreset = "custom"` + 写 `localStorage[CUSTOM_LAYOUT_KEY]` | **校验通过** → 序列化 layout → 触发浏览器下载 `{currentPreset}.json` → 提示"已下载 battle.json，请覆盖到 codes/layouts/ 后刷新页面" → 开始对局，`currentPreset` 不变 |
| 「退出摆子 ✕」（脏） | 恢复 entry preset | **不变**（仍恢复 entry preset 的初始 layout） |
| 档位下拉里的"自定义" | 对应 `localStorage` | 对应 `codes/layouts/custom.json`（文件不存在 = 空局 + 自动进摆子，沿用旧逻辑） |

## 4. 新增工具

`downloadLayoutAsJson`（位置建议：`startFromSetup` 上方，`validateSetup` 下方）：

```js
function downloadLayoutAsJson(presetKey) {
  const data = {
    game: "商周大战",
    preset: presetKey,
    moves: [],
    layout: pieces.map(p => [p.side, p.type, p.col, p.row]),
  };
  const blob = new Blob([JSON.stringify(data, null, 2)], { type: "application/json" });
  const a = document.createElement("a");
  a.href = URL.createObjectURL(blob);
  a.download = presetKey + ".json";
  document.body.appendChild(a);
  a.click();
  document.body.removeChild(a);
  setTimeout(() => URL.revokeObjectURL(a.href), 1000);
}
```

## 5. 边界 / 容错

- **保存校验**沿用 `validateSetup()`（双方各 1 king、双方各 ≥1 小棋子、王不会死局、白方有合法行动）。`validateLoadedLayout`（K10 对称 + 双方各 1 king）继续用于 `loadPresetLayouts` 过滤 `custom.json`。
- **下拉里选 `custom` 但 `custom.json` 不存在**：`loadedLayouts.custom == null` → `initPieces` 拿空数组 → 棋盘空 → 现有"空局自动进摆子"逻辑接管（`<kbd>`：`newGame` 第 2982 行附近）。一行不变。
- **下拉切档时仍调 `newGame()`**：现状（2770 行附近）。不变。
- **`currentPreset` 在摆子后保持原值**：意味着同一会话里可反复进摆子-保存（针对同一档）。这是用户期望。
- **`localStorage` 中旧的 `CUSTOM_LAYOUT_KEY` 数据**：读路径已删除，写路径已删除，旧 key 静默失效无需主动清理。建议保留一行"启动时主动 `removeItem`"非必要——YAGNI。
- **JSON 中历史遗留 `preset` 字段**：写入时统一使用当前 `preset` 键；既有 `codes/layouts/{small,battle,final}.json` 字段已对齐。
- **`sync-index.bat`**：本轮不动；实施完成后正常调用把 `index.html` 与 `codes/商周大战.html` 同步。

## 6. 不做（YAGNI）

- 不主动迁移旧 `localStorage` 自定义数据到 `custom.json`（用户需要时手动导出/导入即可）。
- 不主动 `removeItem(CUSTOM_LAYOUT_KEY)`。
- 不在档位下拉里加"新建空布局"等额外入口。
- 不改"导出布局 / 导入布局"按钮（保留作为带 `moves` 的对局存档通路）。
- 不动 `startFromSetup` 之外的提示文案（仅更新与本轮直接相关的几处）。
- 不动 PRESETS（hard-coded fallback）——`loadedLayouts` 加载是更好的入口。
